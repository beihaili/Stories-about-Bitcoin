## 总评

DeepSeek 版验证了一个方向：第1章开篇确实可以更早压出李觉的现实处境，把房租、母亲语音、裁员和平台派单权重放到第一屏附近，番茄留存会比原文更直接。

但 DeepSeek 版不宜直接采用。主要问题是它把物件背面新增“你还会再来的”式提示，这会把本书的神秘机制推向玄幻外挂，也削弱“中本聪账号不解释机制”的克制感。它还删弱了原文结尾的通胀现实回钩，使“现实刺点 -> 历史照面 -> 认知改写 -> 现实动作”的闭环变窄。

追加 prompt v2 后，DeepSeek 明显更贴合本书：它不再给纸片背面新增硬提示，还主动写“背面是空白”，说明负面约束有效。v2 的现实压力、历史现场和章末悬念都更完整，但仍有两点需要人工编辑：一是“纸很旧/边缘泛黄”出现在1976年现场时略不合时宜；二是章末更偏“这四块五从哪里来”的悬疑，弱于原文“八块与五块”的货币现实回钩。

GPT 再改写版仍更适合作为第1章开篇的改稿底稿：它吸收 DeepSeek 的短段落和现实压力前置，同时保留哈耶克纸片的主题句、物件合规性、回到现实后的价格疑问和普通订单动作。

## 原文开篇

### 优点

- 第一行钩子直接：二十九岁凌晨三点、外卖员、中本聪、1976伦敦，题材承诺清楚。
- 哈耶克现场质感强，英文对话、纸箱、退回赠书、签赠名单都稳。
- 章末“八块和五块之间差了三块”把货币问题落回李觉生活，主题闭环好。

### 风险

- 前半段信息密度高，平台规则、母亲、陈浩、裁员、技术背景连续进入，手机阅读节奏稍重。
- “中本聪下单”出现前铺垫略长，番茄读者的第一屏强钩子可以更早。
- 段落长度相对文学向，中后续整书如果保持这种密度，平台留存会吃压力。

## DeepSeek 版

### 优点

- 现实压力前置有效：房租日账单、母亲语音、裁员回忆、陈浩对照更早成型。
- 短段落推进明显，手机阅读更顺。
- “梦不会让塑料袋勒着手指”这一类句子有可取的现场触感。

### 风险

- 物件背面新增硬提示，破坏“中本聪账号机制不解释”的暗线纪律。
- “Too early”被截短，损失原文“但总得有人先做起来”的主题力。
- 回到现实后的普通订单和价格疑问被弱化，闭环不如原文。
- 整体更像强钩子样章，但不够像本书长期气质。

## DeepSeek Prompt v2 版

### 优点

- 专用 prompt 有效压住了上一版最大问题：没有新增“你还会再来的”硬提示，还明确写出纸片背面空白，符合账号留白纪律。
- 开篇现实压力更干净：电量、账单、七楼送餐、旧工位、母亲语音、接单倒计时都服务李觉处境。
- 历史现场保留了核心对话，煤烟、湿羊毛、旧书、水洼铁锈等感官细节更稳定。
- 章末“四块五已经到账，但不确定从哪里来”有不错的悬疑感，适合番茄读者点下一章。

### 风险

- 在1976年现场就写纸片“很旧、边缘泛黄”略违和，应该改为“纸边被雨气浸软/墨水未干透”一类现场状态，回到现实后再显旧。
- “四块五从哪里来”的悬疑比原文更抓人，但主题上弱于“八块与五块之间差了三块”的货币现实回钩。
- 现实段把第一个送餐地点改成西二旗七楼，与原文小区程序员版本不同；正式嫁接前需要检查第1章后文和第2章是否有重复或错位。

## GPT 再改写版

### 优点

- 第一行把“中本聪”和“房租”并置，题材钩子和现实压力同时出现。
- 平台派单权重、母亲语音、裁员、陈浩对照更早进入，但没有把李觉写成怨气型主角。
- 保留哈耶克签赠名单、主题句和现实价格回钩，符合物件线和章节闭环。
- “这一次，他没有只看导航”比硬写“你还会再来的”更克制，能承接后续成长。

### 风险

- 比原文更商业，但文学余味略少，需要保留原文部分长句的冷感。
- 开篇信息压缩更强，正式替换前应再检查第2章承接，避免重复介绍陈浩和母亲。
- 如果全书都采用这种短段落节奏，可能削弱部分历史现场的沉浸长度，应只在开篇和强钩子章优先使用。

## 决策

不建议直接全章替换，也不建议采用 DeepSeek 原样。Prompt v2 证明“强角色 prompt + 硬约束 + 必留清单”有效，后续 DeepSeek 可以继续用这个模板跑 01-03 章开篇样章。

建议进入“局部嫁接”：

1. 用 GPT 再改写版的第一屏到“他点了接单”重写原文前半，同时参考 Prompt v2 的“七楼旧工位/账本错的是账本身”等句子。
2. 历史照面主体保留原文和 Prompt v2 中较稳的感官细节，避免过度切碎。
3. 章末保留原文“八块与五块”的现实回钩，可吸收 Prompt v2 的“四块五从哪里来”作为额外小悬念。
4. 第2-3章可以继续用 Prompt v2 生成样章，但仍按“开篇节奏改写 + 局部嫁接”处理，不做模型整章替换。

是否扩展到 01-03 章：可以扩展，但方式应是“开篇节奏改写 + 局部嫁接”，不是“DeepSeek 全章替换”。
