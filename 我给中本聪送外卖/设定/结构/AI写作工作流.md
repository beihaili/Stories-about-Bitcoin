# AI 写作工作流

## 先说结论

这本书不能用"一个 AI 一口气写一章"的方式推进。

正确方式是：

1. **设定库是长期记忆**：`设定/` 相当于 Story Bible / Codex，是所有 agent 的事实来源。
2. **章节表是调度中心**：扩写版以 `43章分工表.md` 决定每章在全书里负责什么；`38章分工表.md` 保留为旧版参考。
3. **章节合同先于正文**：每章先生成合同，再拆 scene beats，最后才起草正文。
4. **统一用 GPT-5.4，但角色分开**：章节策划、beat 拆解、正文起草、连续性审稿、风格编辑都可以是同一个模型，但必须按不同 agent 角色串行执行，不能一步到位。
5. **审稿是独立步骤**：不能让同一个起草 agent 自己宣布自己合格。

目标不是让 AI 替作者写完，而是让 AI 像一个稳定的写作工作室：有人策划，有人查史，有人写初稿，有人做连续性审稿，有人做风格定稿。当前这些角色统一由 `GPT-5.4` 承担。

## 参考产品抽象

现有 AI 写作工具可以抽象成五层：

| 产品层 | 常见形态 | 对本书的对应物 |
|---|---|---|
| 长期记忆 | Story Bible / Codex / Knowledge Base | `设定/人物`、`设定/物件`、`设定/历史锚点`、`设定/规则` |
| 结构层 | Acts / Chapters / Scenes / Beats | `故事骨架.md`、`43章分工表.md`、本文件的章节合同 |
| 起草层 | Draft / First Draft / Write | 正文初稿 agent |
| 局部编辑层 | Rewrite / Expand / Describe / Humanizer | 风格编辑、现实段加厚、穿越段加现场、去 AI 味 |
| 校验层 | Prompt preview / eval / brand tone | 连续性审稿、历史锚点审稿、人物语气审稿 |

本书已经有长期记忆和结构层。下一步所有章节都按本文件执行。

## 模型分工

| 模型 | 主要职责 | 不建议承担 |
|---|---|---|
| GPT-5.4 | 总结构、长上下文整合、章节合同、历史锚点、现实段方案、scene beats、正文起草、连续性审稿、风格定稿、文档更新 | 无约束一口气写完一章且不经过合同/审稿链 |
| GPT-5.4 mini / Sonnet / Haiku 等快模型 | 摘要、抽取人物/地点/物件、初步改错、低风险扩写 | 关键章节正文、终局选择、复杂人物冲突 |

### 路由原则

- **先结构，后正文**：先出章节合同，再拆 beats，再写正文。
- **先约束，后生成**：每次生成正文前必须喂本章合同和 scene beats。
- **先审稿，再定稿**：先查规则和矛盾，再做风格编辑。
- **同模型也要分角色**：即使全部使用 `GPT-5.4`，也必须显式区分“策划 / 起草 / 审稿 / 风格编辑”四步。
- **模型 ID 不写死**：实际执行默认主模型为 `gpt-5.4`，快模型仅用于低风险辅助，不替代关键章节正文。

## 当前执行约定

自 2026-04-22 起，《我给中本聪送外卖》的正文生产线**不再依赖 Opus**。

统一约定：

- 章节合同：`GPT-5.4`
- scene beats：`GPT-5.4`
- 正文初稿：`GPT-5.4`
- 连续性审稿：`GPT-5.4`
- 风格编辑：`GPT-5.4`
- 设定回填：`GPT-5.4`

`scripts/novel_opus.py` 可保留为历史工具，但**不属于当前标准写作流程**，后续章节默认不再使用。

## Agent 列表

| Agent | 模型建议 | 输入 | 输出 | 合格标准 |
|---|---|---|---|---|
| 总编 Agent | GPT-5.4 | 故事骨架、38章表、当前进度 | 本章是否该写、写作风险、结构提醒 | 能指出本章在全书里的任务 |
| 章节策划 Agent | GPT-5.4 | 38章表、本章原书锚点、前章摘要 | 章节合同 | 明确现实刺点、历史问题、认知改写、现实动作 |
| 历史锚点 Agent | GPT-5.4 + 搜索 | 原书章节、必要史料 | 历史锚点文件草稿 | 区分史实、艺术加工、不可改事实 |
| 现实线 Agent | GPT-5.4 | 章节合同、人物档案 | 现实段方案 | 现实刺点不是道理，是具体场景 |
| Beat Agent | GPT-5.4 | 章节合同、现实段方案、历史锚点 | 6-10 个 scene beats | 每个 beat 都是可写动作，不是章节摘要 |
| 正文起草 Agent | GPT-5.4 | scene beats、风格规则、人物档案 | 正文初稿 | 不解释设定，不写成科普讲义 |
| 风格编辑 Agent | GPT-5.4 | 初稿、风格规则、示例段落 | 润色稿 | 句子更克制，细节更准，观点更少 |
| 连续性审稿 Agent | GPT-5.4 | 润色稿、全套设定 | 审稿报告 | 查出人物、物件、规则、章节职责是否冲突 |
| 设定回填 Agent | GPT-5.4 | 定稿、审稿报告 | 需要新增/更新的设定项 | 不改正文，只列回填清单或补设定文件 |

## 每章标准流程

### Step 0：准备上下文

必读文件：

- `设定/结构/故事骨架.md`
- `设定/结构/43章分工表.md`
- `设定/结构/10万字扩写方案.md`（扩写新增章与重排时必读）
- `设定/结构/AI写作工作流.md`
- `设定/规则/穿越规则.md`
- `设定/暗线/中本聪账号.md`
- `设定/人物/李觉.md`
- `设定/人物/陈浩.md`
- `设定/人物/母亲.md`
- `设定/人物/赵晴.md`
- 上一章正文
- 本章对应的原书章节

如果本章涉及已带回物件，还要读 `设定/物件/` 对应文件。

### Step 1：章节合同

每章先产出这个，不直接写正文。

```text
章号：
标题暂定：
原书锚点：
叙事形态：
本章结构职责：

现实刺点：
历史问题：
李觉原来的误解：
穿越/历史照面如何改写误解：
回来后的具体动作：

必须出场人物：
禁止出场人物：
需要带回或回收的物件：
中本聪账号状态：
本章留给下一章的情绪或动作：

风险：
- 史料风险：
- 人物风险：
- 结构风险：
- 爽文滑坡风险：
```

### Step 2：Scene beats

每章拆成 6-10 个 beats。每个 beat 写成动作指令，不写成主题总结。

合格 beat：

- 有地点；
- 有在场人物；
- 有一个明确动作；
- 有一个情绪或认知变化；
- 能直接扩写成 300-800 字正文。

不合格 beat：

- "李觉理解了比特币的意义。"
- "讲述中本聪发布白皮书。"
- "表现隐私的重要性。"

合格写法：

- "李觉在麦当劳门口等单，看到 App 后台定位每秒刷新一次。赵晴凑过来看热区，提醒他药店后门最难等。他第一次意识到自己不是在用 App，而是在被 App 记录。"

### Step 3：正文起草

正文起草只允许看本章合同、scene beats、必要设定，不要把全套资料一股脑塞进去。

原因：上下文太多时，模型会倾向总结和解释，正文会变成设定复述。

### Step 4：结构审稿

用 `GPT-5.4` 的连续性审稿角色单独检查：

- 本章有没有完成"现实刺点 → 历史照面 → 认知改写 → 现实动作"；
- 现实动作是不是具体行为；
- 李觉是不是只在旁观；
- 是否违反穿越规则；
- 是否引入未建档的重要人物；
- 物件是否合规、是否需要建立文件；
- 陈浩、母亲、赵晴是否符合人物档案；
- 中本聪账号出现频率是否过高。

### Step 5：文学编辑

用 `GPT-5.4` 的风格编辑角色处理：

- 去掉解释腔；
- 去掉"他意识到/他明白了"这类直白句；
- 增强现实冷感；
- 增强穿越现场细节；
- 保持第三人称限知；
- 保持番茄小说段落长度；
- 让情绪从动作和物件里出来。

### Step 6：设定回填

定稿后只做三类回填：

- 新人物出场 3 次以上：建人物档；
- 新物件带回：建物件档，填写预计回收章节；
- 新历史节点确定：建历史锚点档。

不要每章都扩写设定。设定是为正文服务，不是正文为设定服务。

```text
- 不要把历史锚点写成科普摘要，要写成李觉会被什么刺中。

<输出格式>
```

### 3. 正文起草 Agent

```text
你是《我给中本聪送外卖》的正文起草 Agent。

只写小说正文，不解释，不列提纲。

<风格>
- 第三人称限知，跟着李觉。
- 番茄小说风格：不用 Markdown 标题，不用分割线，不用引用块。
- 段落平均 140-160 字，叙事紧凑。
- 现实段冷峻一点，带黑色幽默；穿越段有现场感。
- 不自夸，不煽情，不讲课。
- 少用"他意识到/他明白了/这意味着"，用动作、账单、物件、对话体现变化。
</风格>

<硬约束>
- 不改变历史走向。
- 不让李觉告诉历史人物未来。
- 每章最多带回一件合规小物件。
- 人物说话必须符合人物档案。
</硬约束>

<章节合同>
{{chapter_contract}}
</章节合同>

<scene_beats>
{{scene_beats}}
</scene_beats>

现在开始写正文。
```

### 4. 风格编辑 Agent

```text
你是《我给中本聪送外卖》的文学编辑 Agent。

任务：在不改变剧情事实、不新增情节的前提下，润色下面正文。

<编辑目标>
- 去掉解释腔和 AI 腔。
- 把抽象判断改成可感知细节。
- 让现实段更冷，穿越段更有现场感。
- 保持第三人称限知。
- 保持番茄小说段落节奏。
- 不要把人物改成观点传声筒。
</编辑目标>

<禁止>
- 禁止新增重大设定。
- 禁止改变历史事实。
- 禁止让李觉说出他不该知道的信息。
- 禁止把陈浩、赵晴、母亲写成工具人。
</禁止>

<正文>
{{draft}}
</正文>
```


## 03 章试运行建议

03 章是最适合验证这套流程的一章。

原因：

- 它对应白皮书和创世危机，是从前传进入比特币本体的门槛；
- 按 `穿越规则.md`，这里可以设计一次"账号静默"，测试没有穿越订单时章节是否仍然成立；
- 赵晴可以首次正式出场；
- 李觉第一次不等中本聪，主动读白皮书，这正好验证"现实动作"原则。

### 03 章最低合格线

- 中本聪账号不下单，静默本身成为信息；
- 李觉在现实里被某个支付、扣款、定位或平台规则刺中；
- 赵晴第一次出现，但不抢主线；
- 白皮书不是科普讲解，而是李觉在现实疲惫中自己打开的一页；
- 章末动作必须是他主动读完第一页 / 记下第一条笔记 / 开始查 `The Times 03/Jan/2009`，三选一或组合。

## 质量红线

- **不要一章一课**：读者不是来上比特币课的，是来看李觉怎么被现实和历史夹击。
- **不要 AI 口播**：凡是"这说明了..."、"他终于明白..."，优先删。
- **不要工具人**：母亲不是稳定观念 NPC，陈浩不是裁员炸点 NPC，赵晴不是底层苦难 NPC。
- **不要过度揭秘账号**：中本聪账号是镜子线，不是侦探线。
- **不要发财爽文滑坡**：价格只能制造诱惑、讽刺和压力，不能成为最终奖励。
- **不要设定膨胀**：新增设定必须服务下一章正文。

## 文件更新规则

每写完一章，最多更新这些文件：

- `正文/NN_*.md`
- `设定/历史锚点/NN_*.md`
- `设定/物件/NN_*.md`（仅当本章带回物件）
- `设定/人物/*.md`（仅当人物弧发生确定变化）
- `设定/结构/43章分工表.md`（仅当章节职责被主动调整）

不要因为某章写出一个好点子，就立刻扩成新世界观文件。先让它在正文里活下来。
