## 核心判断

这本书不适合直接套普通番茄爽文公式。

普通公式强调“身份反转、打脸、暴富、系统奖励”。本书的卖点是“外卖员现实压力 + 神秘订单 + 比特币历史照面 + 现实行动”。如果强行改成暴富爽文，会破坏主题，也会触碰金融引导风险。

因此重写目标不是换题材，而是把既有稿件改成更适合手机留存的商业叙事：

```text
第一屏点住人 -> 前20%压出冲突 -> 中段用历史照面改写误解 -> 章末给下一章压力 -> 全书用现实后果串起来
```

## 六条硬规则

### 1. 第一屏必须有即时压力

每章前 300 字至少出现一种压力：

- 钱：房租、扣款、提现、药钱、站台报价。
- 系统：权重、风控、定位、复核、后台、封控。
- 关系：母亲、陈浩、赵晴、骑手群、亲戚。
- 异常：中本聪订单、缺席、历史物件、账号沉默。

禁止用天气、背景、回顾上章或世界观说明开篇。

### 2. 每章只能有一个主事件

单章必须能回答：

```text
本章删掉哪件事，全书会断？
```

答不上来就说明本章只是知识切片，需要重写成事件。

### 3. 历史信息必须被人物动作消化

不写“比特币是什么”的讲义。

正确写法：

- 李觉看到某个历史场景；
- 他联想到现实里的一个扣款、复核、后台或关系压力；
- 回来后做一件具体的小事。

### 4. 结尾必须有真钩子

章尾钩子优先使用：

- 未完成动作：申诉、工具、转账、删除、公开更正。
- 新压力：赵晴截图、陈浩消息、母亲转账、账号备注。
- 神秘物件：纸片、打印稿、铁盒、留言。
- 两难选择：接不接、删不删、公开不公开、帮不帮。

禁止用空泛主题句收尾。

### 5. 去AI味优先于加文采

执行“三刀”：

- 删解释链：因为、所以、为了、试图、意味着、他意识到。
- 删抽象情绪：震惊、悲伤、复杂、百感交集，改成动作和身体反应。
- 拆长段：手机阅读中超过三四行的段落优先拆开。

### 6. 风控永远优先

不写荐币、带单、收益承诺、操作教程、钱包私钥教程、闪电网络教程、互助池理财化、拉人头。

比特币在本书里是历史和信任议题，不是投资建议。

## AI重写流水线

每章按六步走：

1. 章节合同：确认现实刺点、历史问题、误解、改写、回来后的动作。
2. Scene beats：拆 6-10 个可拍摄动作，不写主题总结。
3. 番茄改写：重写前 20%、压缩解释、强化动作。
4. 风格精修：保留本书冷感和克制，不把李觉写成嘴炮爽文主角。
5. 连续性审稿：检查人物、物件、穿越规则、章节职责。
6. 风控和字数检查：保证不形成金融引导，草稿目标单章 2200-3800 字符。

## 本书情绪标签

主标签不是“暴富爽文”，而是：

```text
都市现实 + 脑洞穿越 + 克制逆袭 + 信任悬疑
```

读者获得的爽点：

- 原来外卖员看见的是更大的系统。
- 原来代码可以不只是饭碗。
- 原来历史不是知识，而是今天规则的前身。
- 原来普通人也能做一点具体的事。

## 分批策略

不一次覆盖 `正文/`。

先写入 `草稿/fanqie_ai_rewrite/`，通过以下检查后再考虑合入：

- 章节标题、顺序、历史锚点无误；
- 每章有现实动作；
- 章尾有下一章压力；
- 没有投资建议或教程感；
- 导出后仍满足番茄 10 万字门槛；
- `git diff --check` 无格式问题。
