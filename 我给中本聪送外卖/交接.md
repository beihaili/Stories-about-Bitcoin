## 核心结构结论

全书不是“穿越讲比特币史”，而是三线咬合：

- A 线：订单 / 穿越 / 比特币史
- B 线：现实生存 / 关系 / 钱
- C 线：中本聪账号 / 李觉自我认知

每章必须完成闭环：

```text
现实刺点 -> 历史照面 -> 认知改写 -> 现实动作
```

如果一章只有“李觉看见历史”，没有回来后的具体动作，就要重写现实段或章末。

## AI 写作工作流

固定流程：

1. GPT-5.4 生成章节合同，不直接写正文。
2. GPT-5.4 拆 6-10 个 scene beats。
3. GPT-5.4 负责正文起草。
4. GPT-5.4 做连续性审稿：人物、物件、穿越规则、章节职责。
5. GPT-5.4 再做风格编辑定稿。
6. GPT-5.4 回填设定文件和索引。

模型分工：

- GPT-5.4：结构、章节合同、scene beats、正文起草、连续性审稿、风格编辑、事实和规则校验、工具调用、文档更新。

当前约定：

- 自 2026-04-22 起，`我给中本聪送外卖` 的标准写作流程**不再使用 Opus**。
- `scripts/novel_opus.py` 保留为历史工具，但后续章节默认不走这条链路。
- 所有新章节都按 `设定/结构/AI写作工作流.md`，统一用 `GPT-5.4` 跑完整链：合同 -> beats -> 初稿 -> 审稿 -> 风格定稿 -> 回填。

## 番茄复制发布流程

不做自动进番茄编辑器，不做 Playwright 自动化。当前方案是生成可复制 TXT。

脚本：

```bash
python3 scripts/export_fanqie_delivery.py --clean
```

默认输入：

```text
我给中本聪送外卖/正文/
```

默认输出：

```text
发布/番茄/我给中本聪送外卖/
```

输出内容：

- `copy.html`：本地一键复制页面，可复制单章或整本。
- `all_chapters.txt`：整本合并纯文本。
- `chapters/*.txt`：一章一份纯文本，第一行是章节标题。
- `manifest.json`：章节清单、字数、风险词、AI 辅助标记。
- `README.md`：发布包说明。

当前导出统计：

- 5 章；
- 正文约 18070 字符；
- 低于本地设置的 20000 字符初始投稿准备线，还差约 1930 字符；
- 风险词命中：比特币、btc、钱包等，发布前人工复核，避免被平台误判为投资建议或交易引导。
